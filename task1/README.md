# Задание 1. Топ-3 и граница по каждому столбцу

## Запуск

```bash
python task1/task1.py input.csv > result.csv                  # inline
python task1/task1.py -r local part1.csv part2.csv            # несколько процессов
python task1/task1.py -r hadoop hdfs:///path/to/input -o hdfs:///path/to/output
```

Выход — по одной строке на столбец, без заголовка:

```csv
metric_id,top3_ids,border_count
```

## Идея решения

Для ответа по столбцу достаточно знать значения на местах 1–4, сколько строк имеют значение 3-го места
и `row_id` строк выше 4-го места (их не больше трёх). Всё остальное можно выбросить.

Поэтому по каждому столбцу собирается **сводка** — список `[value, count, ids]` по убыванию `value`:

- значение хранится, пока строк со строго большими значениями не больше 3, т.е. это все значения,
  занимающие места 1–4;
- `count` — полное число строк с этим значением;
- `ids` — не больше трёх `row_id` на значение: значение с 4 и более строками
  однозначно в топ войти не может.

Сводки **сливаются без потерь** (`merge_summaries`): если значение глобально занимает
место 3 или 4, то в любой части данных выше него меньше 4 строк, поэтому в локальной сводке оно
присутствует с полным `count`. Значит, одна и та же функция работает на всех этапах:

| Этап | Что делает |
|------|------------|
| `mapper_init` / `mapper` | обновляет 9 сводок в памяти (in-mapper combining) |
| `mapper_final` | выдаёт 9 сводок с ключом `metric_id` (1..9) |
| `combiner` | сливает сводки мапперов одного узла |
| `reducer` | сливает сводки и считает ответ |

В reducer по итоговой сводке находятся значения 3-го (`third`) и 4-го (`fourth`) мест:

- `top3_ids` — строки со значением строго больше `fourth` (если 4-го места нет — все строки);
- `border_count` — число строк со значением `third`, если `third == fourth`, иначе 0.

По сети уходит `9 × число мапперов` сводок по несколько элементов вместо 10 млрд × 9 значений.
Память маппера — O(1).

## Решения по неоднозначностям условия

- **Заголовок во входе** пропускается (строка, в которой метрики не парсятся как float).
- **Заголовок в выходе** не пишется: строки приходят из разных reducer-ов.
- **Первый столбец выхода** — номер метрики (`metric_id`, 1..9), как в таблице описания полей.
- **Меньше 4 строк:** 4-го места нет, все строки входят в топ однозначно, `border_count = 0`.
- **Значения сравниваются как float:** `1`, `1.0` и `1e0` — одно значение; `inf` и `-inf` поддерживаются.
- **NaN** не сравним ни с чем и в рейтинге не участвует.
- **Порядок в `top3_ids`** — по убыванию значения, при равных значениях — по `row_id`.
- Значения передаются между этапами как `repr(float)`: без потери точности и без проблем с `inf` в JSON.
